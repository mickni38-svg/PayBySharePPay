# Workflow — Documentation Only

## Evidence

Documentation must be based on:

- source code
- project files
- configuration
- migrations
- tests
- approved use case
- explicit Product Owner decision

Never invent implementation status.

## Early exit

Read only the target document and minimum source evidence.

## Conflict handling

When current code differs from desired behaviour, document:

- current implementation
- desired target
- gap

Do not present planned behaviour as implemented.

## No code changes

If code changes are required, stop and reclassify.
